## 1. 项目概述

### 1.1 背景与现状

MajorTravel 是四人国庆墨尔本旅行（2026/9/30–10/7）的路线规划软件。线上已有一个**单文件演示版**（master 分支 `index.html`，发布于 GitHub Pages：https://litchi-drop.github.io/TheMajorTravel/ ），具备：Leaflet + 天地图/Esri 双底图、蓝本骨架（8 天 46 点位，含 10/2"莫宁顿半岛·轮渡过湾一日游"轮渡环线）、组员加 Pin 后 OSRM 真实道路自动重算、多日多选高亮、去回实线/返程虚线、搜索添加等能力。

演示版的根本局限：行程数据存各自浏览器的 localStorage，**互相看不到、改完不同步、修改无归属、无历史可查**——"四人协作规划"实际上从未发生。

### 1.2 项目目标

本项目（协作版）的双目标：

1. **实用目标**：把"各自的 localStorage"变成"大家共用的服务端行程"，且每次修改都知道是谁在何时干的——邮箱账号注册登录、云端权威数据、修改徽标与可展开历史、自动同步；
2. **学习目标（首要）**：以真实项目带动 **Go 后端 + Vue 前端 + PostgreSQL/Redis 中间件**的完整技术栈学习。选型从"装包即用"转向"能亲手实现核心机制"的路径。

产品演进方向：在小队协作工具之上，远期成长为**路线分享社区**——成员可把自己的路线"发布开源"，他人浏览、复制、提交点位提案，由发起者审核合并（类比 Git 仓库的开源协作模式，见 §11 三期规划）。

一句话验收：**四人各自注册登录，任何人在任何设备上看到同一份行程；每个点位标注"最后由谁修改"，点开可见完整修改历史；一人改动，他人半分钟内可见。**（此为**验收测试场景**＝局域网真机联调；2026 墨尔本之行由演示版承载，见 §1.3 定位决策）

### 1.3 约束与定位

- 项目为**学习驱动**，里程碑按学习节奏给参考工期，不设硬性交付日期；
- 国庆出行工具由 master 单文件演示版兜底，协作版进度不影响出行；
- 一期定位**内部小队工具**（邀请码注册制），数据库按多用户多行程设计，验证后可平滑开放注册并演进社区形态；
- **定位决策（2026-09-02 双向钢人论证后确认）**：本次 9/30–10/7 之行全程由演示版承载，家人在协作版中的角色是**验收测试夹具**而非目标用户；协作版首个真实使用场景为**下次旅行或二期开放注册后的外部用户**。"10/7 后的用户真空"为已接受的参数，不构成进度压力，亦不因旅途临近而改变步骤顺序或压缩质量。

### 2.2 非功能需求

- **学习价值**：优先选择"亲手实现核心机制"的路径（如手写 Redis 限流中间件、标准库 net/smtp 发验证码邮件），前提是工程质量不打折；
- **可用性**：一期服务对象为局域网内开发与家庭测试；二期上云后要求 7×24；
- **性能**：≤10 用户、轮询 30 秒/人、行程数据 <100KB，负载无压力；bcrypt 校验为数百毫秒级，四人规模无感；
- **安全**：密码 bcrypt 哈希存储；验证码/登录接口限流防刷 + 失败锁定；邀请码与成员真实邮箱绝不进公开仓库；
- **可维护**：Go 标准 `cmd/internal` 分层；前端 Vue 组件化；**测试纪律**：核心纯函数（字段 diff、验证码逻辑、密码规则等）以 Go 标准库 `testing` 表驱动测试随 Step 交付——自学无 code review，测试是主要的正确性反馈回路（见 R10）。**分工调整（2026-09-02）**：测试代码的编写与执行移交独立 AI 流程，本仓库交付实现与 curl 联调实录。

### 3.2 为什么是 Go

| 维度 | Go | Java Spring Boot | Python FastAPI | Node.js NestJS |
|---|---|---|---|---|
| 相对拓宽幅度 | ★★★★★（新语言哲学） | ★（全家桶同质化） | ★★★★（动态/AI 范式） | ★★（生态延伸） |
| 与本项目契合（小 API + PG + Redis） | ★★★★★ 甜点区 | ★★★ | ★★★★ | ★★★★ |
| 亲手造轮子的学习素材 | ★★★★★ | ★★ | ★★★ | ★★ |
| 云原生生态与国内就业面 | ★★★★★ | ★★★★ | ★★★ | ★★★ |
| 部署体验（本地→云） | ★★★★★ 单二进制交叉编译 | ★★ JVM | ★★★ | ★★★ |

**结论：Go。** 决定性理由：

1. **语言哲学足够不同，拓宽幅度最大**：极简语法规范、显式错误处理（`if err != nil`，无异常抛接）、组合优于继承（结构体嵌入 + 结构化 interface）、goroutine/channel 的 CSP 并发模型——学的是另一套后端世界观；
2. **"电池少"恰好转化为学习素材**：本项目需要的限流（Redis 计数器 + 中间件）、验证码 TTL（`SET EX` + `GETDEL`）、JWT 校验、bcrypt 密码哈希，在 Go 里都要亲手写，每个业务点都是一次练习；全家桶框架里这些只是"配置一下"；
3. **云原生入场券**：Docker/Kubernetes 等均由 Go 编写，国内大厂 Go 为主力后端栈之一；本项目用 docker compose 编排 Redis，顺带完成容器化学习；
4. **部署故事最简**：Windows 开发机 `GOOS=linux go build` 交叉编译单个二进制（前端还可用 embed 打进去），scp 上云配 systemd 直接跑，零运行时依赖；
5. **与前端拓宽互补**：Vue 承担前端生态拓宽，Go 承担后端范式拓宽，两条线互不重叠。

### 3.5 数据库：PostgreSQL 16（原生 Windows 服务）

- 本机以 EDB 安装包安装原生 PostgreSQL 16，Windows 服务 `postgresql-x64-16`（开机自启，scram-sha-256 认证），监听 5432；
- 相比嵌入式数据库：JSONB（字段级 diff 的天然存储）、真事务隔离、丰富索引类型，且是 Go 生态最常见搭档——四人规模选它为学习而非负载；
- 开发库为 **`major_travel`**（本机共用 PG 实例上的独立库，实例还承载 abp_wms 等其他项目库——代码只连接 major_travel，迁移绝不触碰其他库）；一期开发直连 `postgres` 账号，密码只存本机 `.env`（已 gitignore，不进仓库不进文档）；二期上云前按最小权限收紧为仅拥有本库的专用角色（列入上云清单）；
- 二期上云用同一版本的 Linux 安装或容器，`pg_dump` 迁移数据，零差异。

### 3.6 Redis 的六项用途（一期全用起来，全是教科书练习）

| 用途 | 实现要点 |
|---|---|
| 邮箱验证码存储 | `SET mt:code:{email} {6位码} EX 300`；校验用 `GETDEL`（一次性消费）。验证码不落 PG，TTL 到期自动消失 |
| 60 秒重发限制 | `SET mt:code:cd:{email} 1 EX 60 NX`，NX 失败即拒绝重发 |
| 每日限额 | `INCR mt:quota:{email}:{yyyymmdd}` + 首次 `EXPIRE 86400`，超 10 拒绝；同 IP 维度同理 |
| 登录失败锁定 | `INCR mt:login:fail:{email}`，连续 5 次 `EXPIRE 900` 锁 15 分钟（密码登录防爆破） |
| JWT 登出黑名单 | 登出时 `SET mt:jwt:black:{jti} 1 EX {剩余秒数}`；JWT 中间件先查黑名单再验签 |
| 行程版本号缓存 | 写操作后 `INCR mt:trip:version`，轮询端点直接读 Redis，不打 PG |

二期扩展：AI 推荐结果缓存；三期：排行榜 ZSET、贡献/审核通知。

### 3.7 本地运行环境（Windows）

- **PostgreSQL**：原生 Windows 服务（§3.5），开机自启，无需额外操作；
- **Redis**：Docker Desktop + `backend/docker-compose.yml`（compose 仅含 Redis），`docker compose up -d` 即起。Windows 无官方原生 Redis，Docker 是最顺方案（Memurai/WSL2 为备选）；顺带学习容器编排；
- **Go**：GoLand + Go SDK（`go run` 即起即测；热重载可用 air）；模块代理 `GOPROXY=https://goproxy.cn,direct`；
- **构建与部署形态（Go 标准）**：开发期 `go run`（前端走 Vite dev server）；部署演练期 `scripts/build.ps1` 一键构建——`npm run build` 产出 `frontend/dist`，复制到 `backend/web/` 由 `//go:embed` 打进同一个 exe，`go build` 后即得**自宿主单二进制**，运行它同时提供 API 与前端页面（同源无 CORS）。常驻可选 NSSM 注册为 Windows 服务（自启 + 崩溃拉起），对标二期的 systemd。Go 服务的行业惯例是自宿主（进程自带 HTTP 服务器），反向代理只在需要 TLS/公网入口时引入（二期 nginx），一期不依赖 IIS 这类外部宿主。

```
        ├── map/              # Leaflet 逻辑（自单文件版移植的纯函数）
        └── components/       # 侧栏、徽标、历史弹层…
```

### 4.3 认证流程（邮箱 + 密码 + JWT，Redis 辅助）

```
【注册】POST /api/auth/register {email, password, nickname, inviteCode[, code]}
  ├─ 邀请码校验（MT_INVITE_CODE，不符即拒，返回可展示中文错误）
  ├─ 邮箱唯一性（lower(email) 唯一索引）
  ├─ MT_EMAIL_CODE_ENABLED=true 时必须携带邮箱验证码（GETDEL 一次性比对）
  ├─ 密码规则（≥8 位）→ bcrypt 哈希（明文不落库、不落日志）
  └─ 创建用户 → 直接签发 JWT（注册即登录）

【发邮箱验证码】POST /api/auth/email/code {email}
  └─ 60s 重发检查（SET NX EX 60）→ 每日限额（INCR + EXPIRE 86400）
     → 生成 6 位码 SET mt:code:{email} EX 300
     → net/smtp 发送到邮箱（SMTP 授权码来自环境变量）
     → 开发模式（开关关闭）：不发信，注册免验证码，日志直显验证码便于联调

【登录】POST /api/auth/login {email, password}
  └─ 失败锁定检查 → bcrypt 比对
     （失败则 INCR mt:login:fail:{email}，连续 5 次锁 15 分钟）
     → 签发 JWT（HS256，7 天，claims：uid / email / jti）
     → 前端 localStorage("mt_token")，后续 Authorization: Bearer <token>

【登出】POST /api/auth/logout
  └─ jti 写入 Redis 黑名单（TTL=剩余有效期）→ 前端清 token

失效路径：token 过期/非法/已登出 → 401 → 前端跳 /login
```

限流三档（全 Redis）：同邮箱验证码 60s 1 条 / 天 10 条；同 IP 天 20 条；登录失败 5 次锁 15 分钟。

### 4.4 协作同步模型（最后写入胜出 + 轮询）

- 任何写操作成功后：PG 事务内更新行程与 `updated_at`，Redis `INCR mt:trip:version`；
- 各端 30 秒调 `GET /api/trip/version`（只读 Redis），version 变化才拉全量数据；
- 页面 `visibilitychange` 切回前台立即检查；
- 冲突策略：最后写入胜出（四人规模、编辑频率极低，冲突概率可忽略）；`places.version` 预留，二期可平滑切乐观锁冲突提示。

### 4.5 数据权威与迁移

- PG 为唯一权威；前端 localStorage 降级为：token、底图偏好、最近一次行程快照（断网只读兜底）；
- 首次登录若服务端行程为空且本地有旧版数据 → 一次性询问导入（蓝本正常路径已有种子）。

### 5.1 表清单与关系

```
users 1 ──── * place_revisions * ──── 1 places * ──── 1 days * ──── 1 trips
（验证码不入库，全生命周期在 Redis 内；密码只存 bcrypt 哈希）
```

| 表 | 用途 | 关键点 |
|---|---|---|
| users | 注册成员 | email 唯一（lower 唯一索引）+ bcrypt 密码哈希；phone 留空，二期启用 |
| trips | 行程 | visibility 预留三期"发布开源"；updated_at + Redis version 驱动轮询 |
| days | 天 | d1~d8 蓝本种子化 |
| places | 点位 | ferry 字段承载轮渡语义；软删除保历史 |
| place_revisions | 修改历史 | 字段级 diff 存 **JSONB**，可索引可查询；三期贡献合并复用此表留痕 |

### 5.2 DDL 草案（正式实现由 GORM 迁移生成）

```sql
CREATE TABLE users (
  id            BIGSERIAL PRIMARY KEY,
  email         TEXT NOT NULL,                        -- 登录凭证，写入前统一转小写
  password_hash TEXT NOT NULL,                        -- bcrypt，明文绝不落库
  nickname      TEXT NOT NULL,
  avatar_emoji  TEXT NOT NULL DEFAULT '🙂',
  phone         TEXT UNIQUE,                          -- 二期手机号注册/短信登录时启用
  role          TEXT NOT NULL DEFAULT 'member',       -- owner / member（三期社区扩展 curator）
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_login_at TIMESTAMPTZ
);
CREATE UNIQUE INDEX idx_users_email_lower ON users(lower(email));

CREATE TABLE trips (
  id         BIGSERIAL PRIMARY KEY,
  title      TEXT NOT NULL,
  start_date DATE,
  end_date   DATE,                                -- 2026-09-30 / 2026-10-07
  visibility TEXT NOT NULL DEFAULT 'private',     -- private / published（三期"发布开源"启用，一期恒 private）
  created_by BIGINT NOT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE days (
  id         BIGSERIAL PRIMARY KEY,
  trip_id    BIGINT NOT NULL REFERENCES trips(id),
  day_date   DATE NOT NULL,                       -- 2026-10-02
  title      TEXT NOT NULL,                       -- '莫宁顿半岛 · 轮渡过湾一日游'
  color      TEXT NOT NULL,
  sort_order INT NOT NULL
);

CREATE TABLE places (
  id         BIGSERIAL PRIMARY KEY,
  day_id     BIGINT NOT NULL REFERENCES days(id),
  name       TEXT NOT NULL,
  type       TEXT NOT NULL,
  lat        DOUBLE PRECISION NOT NULL,
  lng        DOUBLE PRECISION NOT NULL,
  desc       TEXT,
  ferry      BOOLEAN NOT NULL DEFAULT false,      -- 到达该站段为轮渡（沿用演示版语义）
  sort_order INT NOT NULL DEFAULT 0,
  version    INT NOT NULL DEFAULT 1,              -- 二期乐观锁预留
  created_by BIGINT REFERENCES users(id),
  updated_by BIGINT REFERENCES users(id),
  updated_at TIMESTAMPTZ,
  deleted_at TIMESTAMPTZ                          -- 软删除，历史可追溯
);
CREATE INDEX idx_places_day ON places(day_id) WHERE deleted_at IS NULL;

CREATE TABLE place_revisions (
  id         BIGSERIAL PRIMARY KEY,
  place_id   BIGINT NOT NULL REFERENCES places(id),
  user_id    BIGINT NOT NULL REFERENCES users(id),
  action     TEXT NOT NULL,                       -- create / update / delete
  changes    JSONB,                               -- {"name":{"old":"A","new":"B"}}
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_revisions_place ON place_revisions(place_id, created_at DESC);
```

蓝本种子（d1~d8 共 46 点位，含 10/2 轮渡环线 233.0km 版本）以 JSON 文件随代码提交，首次启动幂等写入。

## 7. 安全与隐私设计

1. **真实隐私不进公开仓库**：成员真实邮箱、注册邀请码、JWT 密钥、SMTP 授权码全部走本机/服务器环境变量；`.gitignore` 排除 `backend/.env`、`backend/bin/`、`backend/web/`、`node_modules/`、`dist/`、`.idea/`，`.env.example` 只放占位符；提交前 grep 自查；
2. **密码安全**：bcrypt 哈希（成本因子 ≥10），明文不落库、不落日志、不回传前端；登录连续失败 5 次锁定 15 分钟；
3. **验证码安全**：存 Redis 带 TTL 自动销毁 + `GETDEL` 一次性消费，不落库明文；60 秒重发限制 + 每日限额防刷；
4. **数据库账户**：一期开发直连 `postgres` 账号访问本机 `major_travel` 库（密码仅存本地 .env，局域网内使用可接受）；该实例还承载其他项目库，代码只连 major_travel、绝不操作其他库；二期上云前收紧为仅拥有本库的专用角色（最小权限）；
5. **会话安全**：JWT（HS256）密钥来自环境变量不硬编码；claims 含 jti，登出即入 Redis 黑名单，原 token 立即失效；
6. **一期局域网使用**：单二进制直接监听 8080，防火墙仅放行局域网网段；公网上线前必须经 nginx + 正式证书走 HTTPS；
7. **二期上云**：域名 + Let's Encrypt 正式证书；SSH 密钥登录；云安全组仅放行 80/443；
8. **前端 token 存储**：JWT 存 localStorage，本项目无 HTML 注入面，学习项目可接受；二期可迁 httpOnly cookie + CSRF 防护（届时作为学习练习）；
9. **数据备份**：一期本地 `pg_dump` 定期脚本；二期云端每日 cron 备份保留 7 份。

## 11. 二期与三期展望

### 二期（上云与开放）

1. **开放注册 + 手机号**：移除邀请码；接入云厂商短信 SDK（手机号注册/登录，接口契约与邮箱验证码一致）；
2. **WebSocket 实时推送**：gorilla/websocket 替代 30 秒轮询，一人改动秒级广播；
3. **AI 线路推荐**：输入天数/偏好标签（亲子/徒步/咖啡/海景…）→ 服务端代理调用大模型 → 返回候选点位 + 选择理由，成员点一下即加入行程（自动带归属徽标）；
4. **外部接口**：POI 检索、天气、汇率等信息聚合，均走服务端代理隐藏 Key；
5. **会话与合规升级**：httpOnly cookie + CSRF 防护、隐私政策与用户协议、正式域名 + HTTPS。

### 三期（路线分享社区：Git 式开源协作）

1. **发布（开源化）**：行程所有者一键把路线发布为公开路线（`visibility: private → published`，附描述与标签），发布后对所有人只读可见；
2. **探索与排行榜**：浏览/搜索公开路线，拉取他人标记信息；按获赞数、被复制数、贡献通过数等指标排行（SQL 聚合起步，规模大后 Redis ZSET）；
3. **复制（Fork）**：把公开路线复制为自己的私有副本独立编辑演化，副本记录来源（fork 链）；
4. **贡献与审核（Pull Request + Code Review）**：网友对公开路线提交"新增点位提案"（payload 结构同 places 一行）→ 发起者审核：**通过** = 合并进路线并写 place_revisions（天然呈现"该点位由谁贡献"）、**拒绝** = 附原因关闭；全程留痕可追溯；
5. **通知**：贡献提交/审核结果通知（复用二期 WebSocket 通道）。
